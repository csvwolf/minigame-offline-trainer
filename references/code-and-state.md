# 代码、WASM 与状态分析

## 从目标行为追踪

选一个最小可重复操作：取得一次奖励、消耗一个物品、切换一次速度、保存并重启。记录前后状态，查找相关 UI 文案/本地化键、配置项、事件、SDK 方法与调用方，再定位持久化接口。字符串命中只是候选；至少结合调用关系或运行时参数验证。

建立小型入口表：函数/方法、签名、对象来源、前置状态、业务语义、副作用、保存点、证据。由名称猜出的功能必须标注未验证。先观察调用，再以小数值试验，再保存重启读回，最后才做批量或高倍率。

奖励追踪包括回调之后的统计命令、累计记录、会话起点重设和后续档位刷新；mock 请求前确认原客户端依赖哪些状态通知。边界与验收见 [原版流程与完整验收](original-flow-and-verification.md)，不要用新写的业务页面绕过不理解的调用链。

## JS 分支

先格式化副本，保留原模块及 sourcemap（若有）。从加载器、导出对象和配置关联定位业务代码，不因压缩难读就立即重写游戏。允许调试时使用断点、调用栈、字段读写与有限计数日志；临时 wrapper 需保留 this、参数、返回类型、Promise/回调及异常语义，能够恢复。

配置与业务对象分开：数据表说明合法 ID/上限，库存状态说明拥有数量，UI 缓存说明显示值；修改其中一个并不必然更新另外两个。优先调用原变化事件和保存机制。

## Unity WebGL / IL2CPP 分支

1. 校验 WASM 版本头及 section，列出 type、import、function、export、code、data 和可选 name section。先提取元数据索引，避免立刻输出数百 MB WAT。
2. 保留 name section 时，类/方法符号能帮助筛选；剥离符号时结合字符串、元数据、注册表、配置与调用图。IL2CPP 元数据版本必须与解析工具相符，不能拿任意版本布局套读。
3. 还原函数签名后再调用。WASM 函数索引包括**导入的函数**，不能把 import section 中内存、全局、表等非函数条目算入函数偏移。函数 section 与 code section 只对应定义函数。
4. 原本无 JS 导出的内部函数，可以在固定版本上追加 export；添加 hook/global 时更新 section 长度与计数，保持索引一致。不要盲目增删 import 导致原函数索引整体偏移。
5. entry hook 要位于局部变量声明之后，遵守栈类型、控制块、返回类型与 ULEB/SLEB 编码。i32、f32、f64 不可互换；浮点转整数先确认边界，防止 trap/溢出。
6. 托管实例、静态函数、隐藏参数、字符串/数组布局、结构体按值或指针传递，都需通过实际签名和调用方验证。需要 runtime metadata 初始化时沿原调用链处理；不要凭函数名传入任意地址。
7. 使用配置和原数据读取器解释 ID、枚举、数量和上限。内存读写要核对对齐和边界；memory growth 后缓存的 TypedArray 可能失效。临时分配应释放，持有指针要考虑对象/场景生命周期。
8. 补丁以原始 SHA-256 守卫，输出补丁清单、导出列表和新摘要。用 WASM 验证器检查，再实际启动并执行目标操作；静态验证通过不证明业务语义正确。

大 WAT 按目标函数流式提取；单行 JSON 用解析器过滤。不要把一款游戏的索引、地址、类名做成默认常量写入通用 skill。若要保存脚本，参数化原始路径和目标，处理非法输入并测试后再共享。

## 状态与存档交叉验证

显示文本、内存字段、业务 getter、序列化值及重启读回应分开观察。只改显示值会在下一帧被覆盖；只改内存可能没触发事件/脏标记；保存成功也可能在退出时被旧状态覆盖。

容器可能有头部、长度前缀、编码和嵌套 JSON，base64 本身不是加密。解析前验证边界，避免一次试错破坏原存档。校验和或加密存在时先查保存/加载链，不能把解析失败归结为服务器验证。

创建可还原的研究状态，每次只改变一个量，区分设置、增量、消耗、奖励和恢复路径。清理、最高品质、暂停/恢复、回城等边界在本次 Unity 项目中暴露过语义错误，详细见 [客户端案例](client-techniques.md)，不是通用于所有游戏的数值表。

## 最小对照实验

| 要回答的问题 | 有意义的证据 |
|---|---|
| 能否离线运行 | 隔离网络的冷启动、资源完整性、多个目标场景及保存重启 |
| 修改入口是否正确 | 原接口读回 + 原 UI/业务效果 + 持久化重启一致 |
| 是否客户端奖励 | 完整回调与入库调用链，离线保存后仍一致；记录未覆盖路径 |
| 是否由修改器导致卡顿 | 同场景原始/离线基线/修改版对照，调用次数与帧时间同时观察 |
| 能否升级不丢档 | 包名、签名一致，versionCode 增加，覆盖安装及读取原存档 |

只根据已执行的实验报告结论。遇到服务器专有状态、缺失资源或未验证版本，列出具体缺口，不用“应该可以”代替完成。
