# 原版流程与完整验收

用于可运行的离线版、本地修改器和平台/账号依赖适配。游戏专属的 ID、内存偏移、资源、存档与数值留在项目，不放进本参考。

## 原客户端与 mock 的边界

- 保留原页面、插图、提示、事件、命令及导航。平台条件或请求不可用时，定位阻塞的边界，提供必要响应/状态，让原成功回调、入库、结算和返回继续执行。不能以自制礼包说明、关卡列表或结算页替代已存在的原功能。
- 为本地响应记录原请求、字段、使用方、来源与未确认规则。静态配置不证明服务器生成算法已知；只补最小可运行状态，明确近似部分，不把同类游戏的逻辑套进来。
- mock 数据同时受原业务与布局约束。路线节点、可选类型、分段、翻页、可点击范围与背景覆盖要与原界面实际消费方式核对；不能只因存在全部关卡，就把全部数据一次塞进原页。按原资源和可证实的布局适配，未知服务端分段规则标明为本地实现。
- 锁图标可能是有门槛的功能，也可能是没有接入代码的占位。通过组件名称、图标/文字、点击绑定、配置与请求确认，不按位置或外观猜功能，不为占位编造解锁条件。

## 首次进入与升级

使用隔离的新存档记录原版首次启动：落在哪个页面、引导是自动触发还是点击开始后触发、何时完成、完成后去哪里。默认离线版沿用这条链路；用户主动选择跳关等修改时才处理对应状态。不把预解锁、跳教程、额外赠送或富裕测试存档作为普通首启。

新存档测试与覆盖升级分别验证。升级使用现有签名、包名和保存接口，比较升级前后的真实进度；不得为重现首次体验清用户数据。新存档格式或命名空间需要明确迁移/隔离策略，不能把存档没加载成功当成新用户。缺少原账号初始化字段时说明未知值，不声称默认状态已与官方完全一致。

## 累计时长与领奖统计

在线时长、广告次数、领取标志分别追踪。对每个相关原回调，核对它是否重设会话起点、清空临时计数，或依赖服务器先下发累计记录。

- 若原界面使用“已累计值 + 本次经过时长”，在重设起点、领奖确认和持久化前提交本次增量，重启后加载累计值。下一档资格和原界面应读同一累计语义；不要只让显示或领奖校验其中一方正确。
- 不因领取较低档奖励就扣除累计进度，也不自动把其他档标成已领。重试/重复点击不得多发奖励或重复加时；原版确有消耗型门槛时，按其规则实现。
- 依据原规则区分本次会话、当日累计与总累计，确认跨日时区、截止时间、后台/离线是否累计。首页无战斗时也应能保存相关记录，生命周期回调应使用当前存档接口，不能留着已弃用的函数名。
- 广告成功链路可能在奖励回调之外还有统计命令、每日任务、累计档位或本局计数。追踪整个 SDK 成功路径，按原规则接通；覆盖商店资源、商店刷新、补体力和实际存在的局内广告入口。
- 统计放在原统一成功边界或有明确职责的入口，避免 SDK 与奖励处理各加一次。普通免费/付费购买、广告取消和失败不计成功；本地免广告成功计入游戏内统计不代表真的观看了平台广告。
- 旧错误统计先备份，再按可证实的记录恢复；先确认已有统计是否已包含这些行为，不能看到购买记录就再加一次。保存迁移版本/标记，避免重启重复补数；区分已领奖门槛证明的最低时长、可确认的购买历史和无法重建的额外时长/付款方式，不猜值或补发未知奖励。

## 基础修改能力与默认值

先按原枚举、getter 和消费行为区分局外主要货币/体力、局内金币/次数；常用项放在容易找到的位置，不用外围设置代替基础资源。若有生命状态，定位数值设置、原上限恢复和可关闭锁血；若有护盾，核对独立状态及消耗/清除规则。尚未定位的功能明确说明，不能给一个没有实际效果的开关。

锁血在实际伤害/死亡判定中验证，只改血条或动画结束后补血可能已经触发死亡、复活或失败。默认关闭，关闭后恢复正常扣血；不能顺带保护敌人。更高倍率、正收益倍率和无限次数也默认不启用，提供恢复正常控制，尊重暂停与场景生命周期。

跳关是可选修改器操作，不替代原地图或结算。先核对当前层、最高通过、已解锁与功能领取记录，再走原入口刷新；真实的新功能解锁弹窗保留。重做时列出仍需保留的已授权功能，并逐项核对入口和效果。

## 以用户操作链验收

按本次修改涉及的机制选择场景，不把“全部玩法已验证”作为默认结论。使用隔离存档；可用 Web 基线时优先在那里调试，平台专属行为再用设备验证。

| 机制 | 需要观察的完整行为 |
|---|---|
| 首启/引导 | 普通新存档 → 原触发时机 → 原引导完成 → 原页面可继续操作 |
| 领取/商店 | 原入口 → SDK/请求 → 实际入库 → 库存/冷却/任务统计 → 保存重启；失败、普通付款和重复领取分别检查 |
| 在线奖励 | 同日累计达到较高档 → 领低档后较高档仍可领 → 切标签、关弹窗、保存重启 → 更高档可领取且不重复发放；再查原跨日规则 |
| 倍速 | 原动作实际加速 → 换回合/进关/返回/面板暂停恢复 → 设置仍有效 → 关闭覆盖后恢复原控制；不能只看按钮上的数字 |
| 生命/护盾 | getter 与原 UI 一致 → 真实受击/护盾消耗 → 死亡与复活未误触发 → 关闭锁血恢复伤害 → 保存恢复 |
| 地图/资源 | 原结算返回地图 → 背景加载完成 → 滚动首尾/可见范围 → 过分段与 boss → 正确背景、节点及点击范围；不得漏图、遮挡或进入黑底区域 |
| 跳关/升级 | 原有效目标与非法值 → 新功能原入口可用 → 回跳保留最高进度 → 重启/撤销 → 覆盖升级保留存档 |

数据断言、直接调用方法和缩短时间的隔离测试可以帮助定位，但“原按钮可用”的证据应包含选中对应原标签、实际点击目标控件和可见结果。不要在隐藏的页面上调用方法后，把另一页截图当成验收。截图需等待异步资源和过渡结束；黑底、空白、遮罩、过期标题或不对应的页面都要查清。

分别记录 Web、模拟器、真机、构建、安装与存档验证；安装 Success 不证明功能全测通过，断连后不能把未执行的检查写成已验证，也不撤销此前确实完成的安装证据。
