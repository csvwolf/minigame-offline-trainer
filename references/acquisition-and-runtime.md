# 采集与启动还原

## 从现有设备开始

使用现有 SDK/ADB 路径，先 `adb devices -l`，之后命令显式带 `-s <serial>`。以 `shell pm path <package>` 确认宿主包；`dumpsys package` 记录版本和安装情况。只读操作优先，不能为获取日志而清应用数据。

采集完成后，客户端可在 Web 运行时优先用隔离 Web 存档调试，模拟器用于实际需要的平台依赖。识别设备与进程的任务归属，只关闭本任务启动的实例；不为降低 CPU 或恢复连接干扰其他任务。手机未出现时先核对已用 ADB server/连接方式、当前列表和型号，再请求重连；安装授权已明确时，恢复连接后直接完成同签名升级，不重复询问安装许可。

分清三类文件：宿主 APK（可能仅含通用小游戏引擎）、下载到宿主数据目录的代码包、运行过程中按需下载的资源。只解 APK 没找到游戏逻辑，不等于逻辑在服务器。

非 Root 情况检查可读的外部文件、缓存、启动日志、小游戏调试入口和可观察网络。`run-as <package>` 仅适用于允许调试的包；权限拒绝不是路径不存在。Android 应用沙箱和各版本存储权限会限制可见性，如实记录限制。

需要私有缓存且用户允许时，在隔离模拟器复现登录与启动，确认模拟器的提权能力后仅导出目标小游戏目录。模拟器能 Root 不代表用户真机能安全 Root；不顺带解锁或刷入手机。

## 抓到有用的资源而不是一堆日志

在启动前记录时间和目录清单，启动后比较新增文件、大小与修改时间；把 appid/游戏版本、请求 URL 路径和缓存文件建立映射。请求列表保留资源所需信息，删除授权头、Cookie、签名参数和个人标识后再归档。

按需用 logcat 观察加载、解压、引擎初始化和文件失败。网络观察先确认游戏是否使用系统代理；HTTPS 解密需要客户端信任且可能受证书绑定限制。没有请求日志不代表没有联网，可能绕过代理；先检查观察链路。优先利用可访问缓存和客户端加载代码，不将禁用 TLS 验证作为默认方案。

记录触发采集的操作：冷启动、进城、进关、新地图、打开背包、首次广告按钮。渐进下载的游戏只进首页会漏资源；按测试范围补齐，不能把现有缓存称为全量资源。

## 文件识别与解包

先看文件头、实际字节长度与载入代码，再决定是否解压。常见 WASM 头为 `00 61 73 6d`，ZIP 为 `PK`，gzip 为 `1f 8b`，Unity 数据容器可能包含 `UnityWebData1.0`。Brotli 没有可靠的统一魔数，结合 Content-Encoding、加载器和受控解压验证，不按 .dat 后缀下结论。

解压或包目录读取要验证长度、偏移、终止位置和路径穿越，输出独立目录；不覆盖原件。平台自定义代码包先读加载器确定目录表、压缩/加密步骤，不能把不可识别直接判为加密。确认加密时区分可复现的客户端解码路径与无法取得的服务器密钥，说明证据和缺口。

Unity 数据包重点定位资源目录和 IL2CPP 元数据；代码包保留模块路径和大小写；资产包保留原命名、依赖配置与版本映射。创建包含相对路径、大小、SHA-256 和来源的清单，避免多个游戏版本混用。

## 模块与运行时

入口常见为 game.js、配置 JSON 或引擎加载器，但以实际调用为准。还原 require/import/System.register 的解析规则、求值顺序和模块缓存；检查相对路径、循环引用、全局对象、window/self/GameGlobal 以及文件系统适配。

WebGL 移植重点区分三个层次：小游戏平台 API、引擎与宿主的桥接、游戏自身的业务 SDK。广告接口往往位于业务 SDK；修改通用宿主广告函数未必覆盖真正奖励入口。

平台兼容层按调用语义实现：回调是否异步、返回值类型、失败分支、生命周期事件、存储编码和画布尺寸。原 JS 隐含宿主功能时，定位第一处失败及调用栈再补实现，避免整套 API 返回空对象。

资源 URL 映射保留版本/路径关系；本地 MIME、相对基路径、二进制缓冲区和 WASM 初始化回调必须一致。将未知外联记录为待分析项而不是返回假 JSON。避免全局替换域名误改签名、存档键或无关文本。

## 还原广告与存档边界

顺着“按钮 → SDK → 回调 → 奖励业务 → 保存”查证。奖励是否本地入库、是否发出收据验证、是否仅暂时显示变化，需要分别观察。隔离本地版本可以直接进入本地奖励路径；不要产生可提交给平台的伪凭证。

存档按“运行时对象 → 保存 API → 编码/容器 → 存储介质 → 下次加载”追踪。平台账号、平台本地 KV 和云存储是不同层；同账号不同步只是一条线索。后续修改优先业务 API，不直接替换整份用户存档。
